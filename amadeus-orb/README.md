# amadeus-orb

Agent **orb/dots** visual for the DeepSeek Harness conversation header, ported from
`amadeus-v2` (`live2d/orb/agent-visuals.js`).

## What it does
Mounts a fixed top-center orb (animated sphere + dots badge) on the web app and exposes a
global control API:

- `window.amadeusOrb.set(state)` → `window.__amadeusOrbSet(state)` (states: idle / connecting / thinking / tool / tool_done / speaking / done / error / disabled, plus per-tool `tool_<name>` states if registered).
- `window.amadeusOrb.setColors(colors, palette)`
- `window.amadeusOrb.setStyle(styleMap)`

## Layout
- `lib/index.js` — host loader (no-op).
- `lib/client.js` — browser client (generated by `node build.cjs`; inlines the renderer).
- `lib/agent-visuals.js` — the orb renderer bundle (source; 344 KB).

## Rebuild
`lib/client.js` is generated. After editing `lib/agent-visuals.js` or `build.cjs`, run:

```
node build.cjs
```

## Phase auto-driving
The client injects the DSH `uiSession` + `uiConversation` services:

1. `ctx.uiSession.sessionStatus` (`Map<sessionId, { running, pendingInteraction, completionUnread }>`,
   fed by the host's `api-session/status` events) tells whether any session is `running`.
2. While running, the ACTIVE session's trajectory snapshot
   (`ctx.uiConversation.binding(sessionId).target("trajectory")`) refines the state:
   - `runningCalls.length > 0` → `tool`
   - `partial != null` → `speaking`
   - otherwise → `thinking`
3. Not running → `idle`.

`tool_done` / `done` / `error` are not yet distinguished (they would need the settled
trajectory records). Manual control remains available via `window.amadeusOrb.set(...)`.
