# amadeus-harness — Claude Code и Codex как исполнители чата в DSH

Чат можно отдать другому агенту: вместо собственного цикла DSH ход выполняет **Claude Code** или
**Codex** со своими инструментами. Плагин самостоятельный: ни от чего снаружи не зависит, программы
харнесов (Claude Agent SDK с Claude Code и рантайм Codex) ставит сам через `npm` в свою папку
`data/runtime`. Нужны только DSH, Node.js с npm и интернет для установки; работает на любом профиле DSH.

## Как пользоваться

В поле ввода чата, **слева от модели** (рядом с «Workspace Write»), появляется выбор исполнителя:
**DSH** (по умолчанию) / **Claude Code** / **Codex** — только из установленных. Выбор запоминается за
чатом. Настроек у харнеса нет, всё берётся из самого чата:

| Что | Откуда |
|---|---|
| модель | модель, выбранная в чате; харнес идёт к ней через подключение её провайдера (страница «Провайдеры») |
| права | пресет разрешений чата: `read-only` → чтение, `workspace-write` → правки, `danger-full-access` → полный доступ |
| папка | рабочая папка чата |
| рассуждения | уровень рассуждений чата (для Codex) |

Вкладка настроек **«Харнесы»**: у каждого харнеса версия, кнопка «Проверить обновления» (сверка с
реестром npm) и «Установить» (если харнес ещё не установлен или есть новее).

## Как устроено

```
чат DSH → цикл агента → llm.stream(провайдер чата, модель чата) ──(перехват llm/stream)──→ харнес
                                          ответ и шаги ← поток чанков (текст, шаги как «мысли»)
```

- Хост слушает `llm/stream` (waterfall DSH): если у чата выбран харнес, вызов модели выполняет он,
  иначе всё идёт как обычно. Вспомогательные запросы DSH (заголовок, сводка) остаются на модели чата.
- Claude Code ходит на Anthropic Messages API адреса подключения, Codex — на OpenAI Responses API
  (шлюз вроде LiteLLM отдаёт оба, в том числе для не-Anthropic/не-OpenAI моделей). Ключ харнес
  получает из хранилища DSH и только как переменную окружения.
- Адреса подключений (без ключей, только имена) страница отправляет хосту сама (`/amadeus-harness/connections`).
- **Сессия харнеса запоминается по чату**, следующий ход её продолжает. В чат, где раньше работал другой
  исполнитель, предыстория передаётся короткой выдержкой; служебные сообщения DSH в неё не входят.
- Домашние папки харнесов лежат в `data/`, ваши `~/.claude` и `~/.codex` не затрагиваются.

## Установка и обновление

Кнопка «Установить» ставит последнюю версию через `npm install` в `data/runtime` (около минуты на
харнес, на диске вместе около 1 ГБ) и работает в фоне. Обновление ставится поверх. Без установленного
харнеса его нет и в выборе исполнителя в чате.

## Ограничения первой версии

- Инструментов DSH (память, браузер, live2D и т. д.) харнес не видит, а его шаги показываются строками
  в блоке «мысли» (`▸ Read · файл`), не карточками. Подтверждений действий в чате нет: границу задают права.
- Картинки из сообщений не передаются, режим плана DSH не учитывается.
- Модель должна быть из подключения с адресом (`llm-pi-ai`). У `deepseek-official` и аккаунта DeepSeek
  адреса в настройках нет, харнес на них объяснит это сообщением.
- Codex через Responses API LiteLLM отвечает заметно медленнее (десятки секунд даже на пустяк), Claude Code быстрее.

## Файлы

| Файл | Что |
|---|---|
| `lib/events.js` | события Claude Code / Codex → общий словарь → чанки потока DSH; сборка промпта |
| `lib/claude.js`, `lib/codex.js` | запуск Claude Code (Agent SDK) и Codex (`codex exec --json`) |
| `lib/adapter.js` | ход чата харнесом: подключение, ключ, папка, права, сессии |
| `lib/runtime.js`, `lib/versions.js` | где лежат программы; версии, реестр npm, установка |
| `lib/index.js` | хост: перехват `llm/stream`, выбор по чатам, `/amadeus-harness/*` |
| `lib/client.src.js` → `lib/client.js` | выбор в композере и страница «Харнесы» (`node build.cjs`) |
| `data/` | выбор по чатам, подключения, сессии, домашние папки, `runtime/` (в git не входит) |

Тесты: `node --test test/events.test.mjs test/adapter.test.mjs`.
